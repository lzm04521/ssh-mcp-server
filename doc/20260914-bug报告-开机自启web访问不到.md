## 修复方案（v1.1.6 已实现）

1. **VBS 隐藏启动器**（`src/services/autostart-service.ts` 重写）：HKCU Run 改为 `wscript.exe //B "%LOCALAPPDATA%\SshMcpServer\autostart.vbs"`；wscript 为 GUI 子系统进程，登录零弹窗。VBS 运行时解析 node：fnm 默认别名（`%APPDATA%\fnm\aliases\default\node.exe`，升级不变）优先 → 启用时实路径兜底 → PATH 裸 `node` 最后。
2. **幂等启动**（`src/index.ts`）：`--admin` 先探测端口（复用 `probeAdminServer`），已有实例则日志+退出码 0；EADDRINUSE 竞态落败再探测确认后优雅退出。
3. **realpath 锚定**（`stdio-proxy.ts` / `restart-helper.ts`）：拉起 daemon 前对 execPath/入口脚本 realpath，剥掉会话级符号链接。
4. **启用前校验**：入口脚本位于 `fnm_multishells` / `_npx` 时拒绝启用并提示 `npm install -g`。

### 修复中发现的隐藏坑（排障记录）

VBS 初版日志目标复用 `daemon.log` 时**整条命令静默不执行**。逐层二分实验（最小 VBS → 字面量路径 → ProgramData 新旧文件）定位：**cmd 的 `>>` 以严格共享模式打开文件，daemon.log 被常驻进程 stdout 句柄长期持有（Node 全共享打开），cmd 追加即 sharing violation**——交互式 cmd 实测报"另一个程序正在使用此文件"；隐藏窗口下该报错完全不可见。Git Bash 能追加是因 MSYS 用全共享模式，造成"权限正常"的假象。修正：VBS 日志独立为 `autostart.log`（daemon 不持有它；重复执行 VBS 时若 daemon 持有 autostart.log，cmd 静默跳过——而此时幂等语义本来就该退出，无副作用）。

## 总结与建议

主因：**Run 键直启 node 控制台程序弹出可见终端窗口，窗口被关即服务被杀**；叠加**多实例并发 EADDRINUSE 风暴**造成登录后端口闪断。v1.1.6 以"wscript + VBS 隐藏启动器（fnm 别名动态解析）+ daemon 幂等启动 + realpath 锚定"根治。本机自启已迁移至新形态并验证。

建议下一步：
1. 发布 v1.1.6 到 npm 后，在 V:\Npm 全局安装执行在线更新（管理台「检查更新」或 `npm i -g`），使自启链路上的 daemon 具备幂等能力；
2. 下次重启登录验证：应无终端窗口弹出，`autostart.log` 出现 `Admin server listening on 127.0.0.1:61125`；
3. 当前 PID 52448（multishell 幽灵路径实例）无需手动处理：下次版本比较/重启自然换新为新路径实例。
